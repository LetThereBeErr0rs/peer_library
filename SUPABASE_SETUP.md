# Supabase setup (production database + storage)

Peer Library uses **Supabase PostgreSQL** for data and **Supabase Storage** (a
private bucket + signed URLs) for files in production. The application code and
configuration are already implemented; this guide covers provisioning the
remote resources and wiring the environment.

> Supabase occasionally renames dashboard sections. If a label below differs,
> use the official docs: <https://supabase.com/docs>. Storage API reference:
> <https://supabase.com/docs/reference/python/storage-from-upload>.

## 1. Create a project

1. Sign in at <https://supabase.com> and create a new project.
2. Choose a region close to your users and set a strong database password
   (store it in your password manager — you will need it for `DATABASE_URL`).

## 2. Get the connection information

In your Supabase project dashboard:

- **Project URL & keys** — *Project Settings → API*:
  - `Project URL` → `SUPABASE_URL`
  - `service_role` secret key → `SUPABASE_SERVICE_KEY`
    (server-side only — it bypasses Row Level Security; **never** expose it to
    the browser or commit it).
- **Database connection string** — Click **Connect** in the top navigation bar (or *Project Settings → Database*):
  - **Option A: Direct Connection (Port 5432) — Preferred when supported:**
    If your deployment environment supports direct outbound IPv6 traffic (or you have the Supabase IPv4 add-on), select **Direct connection** (port `5432`):
    ```
    postgresql://postgres:<password>@db.<project-ref>.supabase.co:5432/postgres
    ```
  - **Option B: Session Pooler (Port 5432) — Recommended for Render (IPv4):**
    Render's standard web services operate in an IPv4 environment. Select **Connection Pooling**, choose **Mode: Session**, and use port **`5432`**:
    ```
    postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres
    ```
    *Note:* Copy the actual host and pooler port (`5432`) directly from your Supabase Connect modal. Never fabricate the host or project reference.
  - **Do NOT use the Transaction Pooler (Port 6543):**
    Port `6543` connects to Supavisor in *Transaction Mode*. This mode is designed for ephemeral serverless functions (e.g. AWS Lambda / Vercel Edge). It breaks prepared statements and session-level state used by SQLAlchemy and psycopg in persistent Gunicorn application workers. Always use port `5432` (Direct or Session Pooler).

Put the selected URI in `DATABASE_URL`. The app automatically upgrades `postgres://` /
`postgresql://` to the `postgresql+psycopg://` driver form.

## 3. Create the storage bucket

1. Go to **Storage → Buckets → New bucket**.
2. Name it `resources` (or set `SUPABASE_BUCKET` to your chosen name).
3. **Keep "Public bucket" OFF** — the bucket must be private. Downloads are
   served through short-lived signed URLs generated by the server.

### Storage access policies

The server uses the `service_role` key, which bypasses Storage RLS, so **no
additional storage policies are required** for the app to upload, sign and
delete objects. Do **not** add public-read policies to this bucket — that would
defeat the private/signed-URL model. (Only add RLS policies if you later let the
browser talk to Storage directly with the anon key, which this app does not.)

## 4. Configure the environment

In your `.env` (or deployment secrets):

```ini
FLASK_ENV=production
SECRET_KEY=<a long random string>           # python -c "import secrets;print(secrets.token_hex(32))"
# Render / IPv4: Supabase Session Pooler (port 5432)
DATABASE_URL=postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres
# Or Direct Connection (port 5432, if IPv6 supported):
# DATABASE_URL=postgresql://postgres:<password>@db.<project-ref>.supabase.co:5432/postgres
STORAGE_BACKEND=supabase
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SERVICE_KEY=<service_role key>
SUPABASE_BUCKET=resources
SUPABASE_SIGNED_URL_TTL=120
SESSION_COOKIE_SECURE=true
```

Never commit `.env`; it is gitignored. `.env.example` holds placeholders only.

## 5. Apply migrations

With the production environment loaded:

```bash
export FLASK_APP=app
flask db upgrade
```

This creates the `users`, `resources` and `resource_files` tables in the
Supabase PostgreSQL database. Run it as a one-off step (or let the container
entrypoint run it once — set `RUN_MIGRATIONS=0` on additional web replicas to
avoid concurrent migrations).

## 6. (Optional) import legacy data into Supabase

```bash
python migrate_legacy.py --dry-run        # preview against the remote target
python migrate_legacy.py --yes            # import (explicit confirm for remote)
```

The importer refuses to write to a non-SQLite target without `--yes`, backs up
the legacy source first, and never deletes it. Note: legacy files referenced
with `storage_backend=local` are not auto-uploaded to Supabase by this script;
re-upload them through the app if you want them served from Storage.

## 7. Verify database connectivity

```bash
export FLASK_APP=app
python -c "from app import app; from extensions import db; \
import sqlalchemy as sa; \
app.app_context().push(); \
print(db.session.execute(sa.text('select 1')).scalar())"
# prints: 1
```

Or list the tables from the Supabase dashboard **Table Editor**.

## 8. Verify a real upload and download

1. Start the app in production mode (or point a staging instance at Supabase).
2. Register/log in, open **Contribute**, and upload a small PDF.
3. On the resource detail page click **Download** — the server generates a
   signed URL from the private bucket and the file downloads.
4. Confirm the object appears under **Storage → resources** with a random
   (UUID) key, not the original filename.

## Troubleshooting

- **`Invalid production configuration`** — a required variable is missing; the
  error lists which (SECRET_KEY, DATABASE_URL non-SQLite, STORAGE_BACKEND,
  SUPABASE_*).
- **DB connection refused / timeout** — check the host and port (use port
  `5432` with the Session Pooler or Direct Connection; do NOT use port `6543`),
  verify the password, and ensure your deployment platform has network access.
- **`Could not create signed URL`** — verify `SUPABASE_SERVICE_KEY` is the
  `service_role` key and `SUPABASE_BUCKET` matches the bucket name.
- **Downloads 404/410** — the object key in `resource_files.storage_key` must
  exist in the bucket; files uploaded while in `local` mode are not in Supabase.
- **SSL/driver errors** — ensure `psycopg[binary]` is installed (it is in
  `requirements.txt`).
